# 02. 시스템 아키텍처

## 1. 개요

로컬에서 실행되는 **Streamlit 앱**이 영상 분석 파이프라인을 오케스트레이션한다.
영상은 **매일 업로드 즉시 전체 파이프라인이 자동 실행**되어 관찰 후보를 **누적**하고,
교사는 **1~2주 주기**로 누적 후보 기반 **주간 초안**을 검토·확정한다.
무거운 비전 분석·STT는 **클라우드 AI API**(또는 로컬 모델)에 위임하되,
원본 영상은 로컬에 보관하고 **선별된 프레임/클립만** 외부로 전송한다.
**얼굴 검출·임베딩·매칭은 로컬에서만** 수행하며, 얼굴 참조사진·임베딩은 외부로 전송하지 않는다.

```
┌─────────────────────────────────────────────────────────────┐
│ 로컬 PC (온프레미스)                                          │
│                                                              │
│  ┌──────────────┐      ┌────────────────────────────────┐   │
│  │ app/ (UI)    │────▶│ services/ (분석 파이프라인)      │   │
│  │ Streamlit    │      │  video → vision → audio → map   │   │
│  └──────────────┘      └───────┬───────────────┬────────┘   │
│         │                      │               │            │
│         ▼                      ▼               │            │
│  ┌──────────────┐      ┌──────────────┐        │            │
│  │ storage/     │◀────│ core/ schemas │        │            │
│  │ SQLite +JSON │      └──────────────┘        │            │
│  └──────────────┘                              │            │
│         │                                      │            │
│  ┌──────────────┐   ┌──────────────┐           │            │
│  │ data/ videos │   │ security/    │           │            │
│  │ frames (제한)│   │ audit·삭제   │           │            │
│  └──────────────┘   └──────────────┘           │            │
└────────────────────────────────────────────────┼────────────┘
                                                  ▼
                    선별 프레임/클립 + 텍스트  ┌──────────────────┐
                    ───────────────────────▶│ 클라우드 AI API   │
                                             │ 비전 LLM / STT    │
                                             └──────────────────┘
```

## 2. 레이어와 책임

| 레이어 | 디렉토리 | 책임 | 의존 |
|--------|----------|------|------|
| UI | `app/` | 화면, 사용자 입력, 결과 표시. **도메인 로직 없음** | services, storage, core |
| 도메인 | `core/` | Pydantic 스키마, 상수(누리 5영역 등). 순수 모델 | 없음 |
| 서비스 | `services/` | 영상·비전·오디오·매핑·파이프라인. UI 비의존 | core, storage |
| 저장소 | `storage/` | repository 인터페이스 + SQLite 구현 | core |
| 리소스 | `resources/` | 누리/KICCE 기준 데이터(JSON) | 없음 |
| 보안 | `security/` | 접근 제어·감사 로그·삭제 정책 | storage |
| 설정 | `config.py` | 경로·API 키·비용 상한 (pydantic-settings) | 없음 |

## 3. 서비스 구성 (`services/`)

- `video/`: 장면 분할(PySceneDetect), 프레임 추출(OpenCV), 품질 필터(Laplacian), **근거 클립 추출**.
- `vision/`: 비전 LLM **어댑터 인터페이스** + 구현(제공자별). 입력 구성·출력 파싱.
- `audio/`: 오디오 분리(ffmpeg) + STT(faster-whisper). **보조** 텍스트 생성.
- `mapping/`: 누리 영역 분류 + **KICCE 문항 후보 매핑(핵심)**. 척도 **플러그 인터페이스**.
- `face/`: 얼굴 검출·임베딩·**가명 매칭 후보**(동의 기반, 후보만, 로컬 전용).
- `dashboard/`: 유아별·누리영역별 **수집 현황** 집계(부족 영역 플래그).
- `draft/`: 누적 후보 기반 **주간/격주 관찰기록 초안** 생성(대표 근거 클립 선정).
- `pipeline.py`: 단계 오케스트레이션(업로드→분할→추출→클립→(오디오)→비전→(얼굴 매칭 후보)→통합→매핑→**누적**). 업로드 즉시 자동 실행(동기).

## 4. 데이터 흐름

**A. 매일 자동 누적 (업로드 즉시 동기 실행)**
1. 교사가 클래스·`captured_date`와 함께 영상 업로드 → `data/videos/`(제한 접근) 저장, `audit_log` 기록.
2. `pipeline`이 장면 분할 → 프레임 추출 → **근거 클립 추출** → (보조)STT.
3. `vision` 어댑터가 구간/클립별 프레임+텍스트를 외부 API로 전송 → 관찰 후보 JSON 수신.
4. (동의 ON 시) `face`가 검출 얼굴 ↔ 등록 참조사진 임베딩을 **로컬 비교** → 가명 매칭 **후보** 생성.
5. `core/schemas`로 검증 후 `storage`에 저장, `mapping`이 누리 영역·KICCE 문항 후보 부착 → **후보 누적**.

**B. 수집 현황 확인 (수시)**
6. `dashboard`가 유아×누리영역 집계 → 교사가 부족 영역 확인·보완 촬영.

**C. 주간 확정 (1~2주 주기, 교사 트리거)**
7. 교사가 기간·대상 선택 → `draft`가 누적 후보를 유아·영역별로 묶어 **주간 초안 + 대표 근거 클립** 생성.
8. 교사가 매칭 확정·후보 채택/수정/기각 → `final_record`(주차 메타) 저장.
9. 연구자가 리포트 열람·export(미디어 경로 제외).

## 5. 배포 형태

- **1차**: 단일 로컬 머신에서 `streamlit run`. 비전/STT는 클라우드 API 호출(또는 로컬).
- 비밀값은 `.env`로 주입, git 제외.
- 원본 영상은 외부로 나가지 않음(선별 프레임/클립만).

## 6. 확장 경로 (2차 이후)

| 현재(1차) | 확장 |
|-----------|------|
| Streamlit UI | **Next.js** 프론트엔드 |
| 업로드 즉시 동기 자동 실행 | (검토 후) **비동기 워커/스케줄러**로 분리 |
| 파이프라인 직접 호출 | **FastAPI** REST 백엔드로 분리 (계약은 [04_API_SPEC.md](04_API_SPEC.md)) |
| SQLite | **PostgreSQL** (repository 인터페이스 교체) |
| KICCE 단일 척도 | 친사회성·놀이몰입·자기조절 등 **다중 척도**(mapping 플러그) |
| 인메모리 그래프 투영(NetworkX) | (실증 시) **영속 그래프 분석 레이어** — 단, CLAUDE.md 원칙 개정·IRB 전제, 민감정보 미저장 |

> **자동 분석은 V2-MVP에서 업로드 즉시 동기 실행**이며, 별도 스케줄러/데몬은 도입하지 않는다.
> 그래프 분석이 필요하면 SQLite에서 **재생성 가능한 인메모리 투영(NetworkX)**으로 한정한다(Neo4j 미사용, [03_DATA_MODEL.md](03_DATA_MODEL.md) 그래프 투영 절 참조).
> 확장 용이성을 위해 **UI ↔ 서비스 ↔ 저장소**를 강하게 분리하고,
> 외부 의존(비전/STT/DB)은 모두 인터페이스 뒤에 둔다. 얼굴 임베딩 어댑터도 동일.
