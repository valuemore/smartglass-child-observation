# 00. 개발 계획 — 스마트안경 유아 행동 관찰기록 보조 시스템

## Context (배경 및 목적)

어린이집 교사가 착용한 스마트안경으로 촬영한 **교사 시점(1인칭) 관찰 영상**을 **매일 업로드·자동 분석**해
유아의 행동·상호작용·활동 맥락 관찰기록 **초안(후보)** 을 **누적**하고, 교사가 **수집 현황을 수시 확인**한 뒤
**1~2주 주기로 검토·확정**하는 **상시 현장 검증형** 연구용 웹 시스템(V2).

- **1차 목표**: 학회 발표용 시연 시스템 (1~2주 매일 업로드·자동 누적 → 수집 현황 확인 → 주간 초안 확정 → 지원도 지표)
- **2차 목표**: 논문용 프로토타입 (AI 후보 vs 교사 확정 비교 등 유효성 지표 산출)

> **운영 모델 전환(V1→V2)**: V1의 "영상별 후보 생성 → 교사 후보별 검토 → 확정" 단발 구조에서,
> **매일 자동 누적 → 수집 현황 확인 → 주기적 주간 초안 확정** 구조로 전환한다.

### 절대 원칙 (설계 전반에 강제)
- AI 분석의 **중심 데이터는 영상**(교사 시점). 오디오는 **보조 증거**일 뿐이다. 사진·음성을 1차 기록 수단으로 쓰지 않는다.
- AI는 관찰기록을 **확정하지 않는다.** 후보·초안만 제시하고, 교사가 검토·수정·확정한다.
- AI는 유아를 자동 확정 식별하지 않는다. `child_A`, `child_B` 임시 ID를 부여하고, 등록된 **얼굴 참조사진 대비 가명 매칭 후보 + 신뢰도**까지 제시하며, **확정은 교사**가 한다. 얼굴 매칭은 **기본 OFF·연구 동의 시에만 ON**이며, 검출·임베딩·매칭은 **로컬에서만** 수행한다.
- 1차 분류 기준 = **누리과정 5개 영역**. **KICCE 유아관찰척도 59문항 매핑은 핵심 기능**(연구로 1차 검증된 관찰 지표). 단, AI는 **문항 후보를 제시할 뿐 확정하지 않으며**, 교사의 관찰기록 판단을 지원한다. 향후 친사회성·놀이몰입·자기조절 등 심화 척도로 매핑을 확장한다.
- **관찰수준 점수·발달 점수·평정 점수는 산출하지 않는다.**
- 교사는 **매일 개별 후보를 검토하지 않으며**, 수집 현황만 확인하고 **1~2주 주기로 확정**한다.
- 원본 영상·**얼굴 참조사진·얼굴 임베딩**은 **제한 접근 · 접근 로그 · 삭제 정책**을 가지며 외부로 전송하지 않는다.
- 영상 전체를 외부 API에 보내지 않는다. **장면 분할 후 주요 프레임/짧은 클립 단위**로만 전송한다. **얼굴 참조사진·임베딩도 전송 금지.**
- 유아 **실명 미저장**(가명 ID만), export에 **미디어 경로 미노출**.
- Neo4j 미사용(그래프 분석은 SQLite 파생 **인메모리 투영(NetworkX)** 으로 한정). 1차는 SQLite + 로컬 JSON/CSV. 모듈을 분리해 향후 PostgreSQL/FastAPI/Next.js 확장이 가능하게 한다.

## 1. 최종 기술 스택

| 영역 | 선택 | 비고 |
|------|------|------|
| 언어 | Python 3.11+ | 단일 언어 코드베이스 |
| UI | **Streamlit** | 교사 검토 화면 + 연구자 리포트 |
| 영상 디코딩/오디오 추출 | ffmpeg, OpenCV | 프레임 디코딩, 오디오 분리 |
| 장면 분할 | **PySceneDetect** (content-aware) | 컷/장면 경계 검출 |
| 프레임 품질 필터 | OpenCV (Laplacian 분산) | 흐림/저품질 프레임 제거 |
| 비전 분석 | 클라우드 멀티모달 LLM API (Gemini / GPT-4o / Claude 중 1개) | **이미지(프레임/그리드)·근거 클립 입력**. 어댑터로 교체 가능 |
| 오디오 전사(보조) | faster-whisper (로컬 우선) | 타임스탬프 포함 STT |
| 얼굴(동의 기반) | 로컬 얼굴 검출·임베딩 (어댑터 교체 가능) | **로컬 전용**. 가명 매칭 후보 생성, 전송 금지 |
| 저장소 | **SQLite** (1차) + JSON/CSV export | repository 패턴으로 추상화. 원천 저장소(향후 PostgreSQL) |
| 설정 | pydantic-settings + `.env` | API 키, 경로, 비용 상한 |
| 로깅/감사 | Python logging + `audit_log`·`ai_assistant_log` 테이블 | 영상·얼굴·분석·동의·삭제·AI비서 기록 |

**배포 형태**: 로컬 앱(온프레미스) + 비전/STT 분석 시에만 클라우드 AI API 호출.
**업로드 즉시 전체 파이프라인이 자동 실행**(동기, 별도 스케줄러 미도입)되어 후보를 누적한다.
원본 영상·얼굴 참조사진·임베딩은 로컬 제한 접근에 보관, 외부로는 선별된 프레임/클립만 전송.

## 2. 영상 중심 AI 분석 파이프라인

```
[A. 매일 자동 누적 — 업로드 즉시 동기 실행]
[1] 업로드/검증     클래스·촬영일과 함께 업로드, 메타 추출, 제한 디렉토리 저장 + 접근 로그
        ↓
[2] 장면 분할       PySceneDetect로 콘텐츠 기반 장면 경계 검출 → 시간 구간 목록(segments)
        ↓
[3] 프레임 추출     장면별 대표 프레임 + 품질 필터 + 프레임 수 상한(비용 통제)
        ↓
[4] 근거 클립 추출  관찰 가치가 높은 구간을 짧은 클립으로 추출(대표 근거용)
        ↓
[5] (보조) 오디오   ffmpeg 오디오 분리 → faster-whisper STT(타임스탬프) → 구간 시간 정렬
        ↓
[6] 비전 분석       구간/클립 단위로 프레임(+STT)을 비전 LLM에 전송 → 관찰 후보 JSON
        ↓
[7] 얼굴 매칭 후보  (동의 ON 시) 검출 얼굴 ↔ 등록 참조사진 임베딩 로컬 비교 → 가명 매칭 후보(제안)
        ↓
[8] 후보 통합·매핑  temp_child_id 정규화 → 누리 5영역 분류 → KICCE 문항 후보 부착 → 후보 누적

[B. 수시] 수집 현황 집계   유아×누리영역 매트릭스, 부족 영역 플래그

[C. 1~2주 주기, 교사 트리거]
[9]  주간 초안 생성  누적 후보를 유아·영역별로 묶어 초안 + 대표 근거 클립(1~3) 생성
        ↓
[10] 교사 검토·확정 얼굴 매칭 확정, 후보 채택/수정/기각, 자유 편집 → final_record(주차 메타)
        ↓
[11] 리포트          유아·주차별 관찰기록 + AI 지원도 지표(미디어 경로 제외 export)
```
- 각 단계 산출물은 SQLite + JSON으로 저장 → 재현 가능, 단계 재실행 가능.
- **A는 업로드 즉시 자동 실행**되며 교사 후보 검토 게이트가 없다(동기 처리, 스케줄러 미도입).
- 외부 전송은 [6]에서만 발생하며, **선별된 프레임/클립 + 해당 구간 텍스트**로 한정. **얼굴 참조사진·임베딩·원본 영상 미전송.**

> 파이프라인 상세는 [05_AI_PIPELINE.md](05_AI_PIPELINE.md) 참조.

## 3. 개발 단계

### 3-1. V1 (완료) — 단발 시연 골격

| 단계 | 내용 |
|------|------|
| P0~P8 | 셋업·영상 파이프라인·비전 분석·KICCE 매핑(핵심)·교사 검토 UI·오디오 보조·연구자 리포트·보안/정책·시연 리허설 |

> V1은 "영상별 후보 생성 → 교사 후보별 검토 → 확정" 구조로 구현 완료. V2는 이 자산(클립 추출·KICCE 매핑·검토 카드·감사 로그)을 재사용한다.

### 3-2. V2 (진행) — 상시 현장 검증형

| 단계 | 내용 | 산출물 |
|------|------|--------|
| **V2-0 문서** | 문서 10종 V2 갱신(본 문서 포함) | 갱신된 docs/* + CLAUDE.md + README |
| **V2-1 데이터 모델** | class_group·child·clip·face_match_candidate·weekly_draft·ai_assistant_log + 마이그레이션 | 확장된 스키마 |
| **V2-2 우리반 설정** | 클래스·유아 등록, 동의 기반 얼굴 참조사진 저장(기본 OFF) | `0_우리반_설정` 화면 |
| **V2-3 일일 자동 분석** | 업로드 즉시 자동 실행 + 진행률·상태머신·재시도 | `1_일일_영상_기록` 화면 |
| **V2-4 얼굴 매칭** | 로컬 임베딩 비교 → 가명 매칭 후보(동의 ON 시, 후보만) | `FaceMatchService` |
| **V2-5 수집 균형** | 유아×누리영역 매트릭스 + 부족 영역 보완 안내 | `2_수집_균형` 화면 |
| **V2-6 주간 초안** | 기간·대상 초안 생성 + 대표 근거 클립 + 확정 | `3_주간_관찰초안` 화면, final_record(주차) |
| **V2-7 AI비서·Safe AI** | 제한형 비서(검색·수정보조·촬영제안) + Safe AI 패널 | 사이드바 공통 |
| **V2-8 리포트·export** | AI 지원도 지표 + 미디어 경로 제외 export | `4_연구자_리포트` 확장 |
| **V2-9 보안 회귀·리허설** | 전송·삭제·감사 종합 점검, 1~2주 누적 전 흐름 리허설 | 보안 점검·발표 시나리오 |

> 권장 순서: **V2-0 → V2-1 → V2-3(자동분석) → V2-5(균형) → V2-2/4(등록·얼굴매칭) → V2-6(주간초안) → V2-7 → V2-8 → V2-9**.
> 단계마다 **security-privacy-reviewer**로 얼굴 데이터·전송·삭제·감사 점검, **test-debugger**로 회귀 확인.
> 척도 확장(친사회성·놀이몰입·자기조절)은 KICCE 매핑의 플러그 인터페이스 위에서 2차 진행.
