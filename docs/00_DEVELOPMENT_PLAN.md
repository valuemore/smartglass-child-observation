# 00. 개발 계획 — 스마트안경 유아 행동 관찰기록 보조 시스템

## Context (배경 및 목적)

어린이집 교사가 착용한 스마트안경으로 촬영한 **교사 시점(1인칭) 관찰 영상**에서,
유아의 행동·상호작용·활동 맥락을 AI가 분석해 **관찰기록 초안(후보)** 을 생성하는 연구용 웹 시스템.

- **1차 목표**: 학회 발표용 시연 시스템 (샘플 영상 업로드 → 배치 분석 → 교사 검토 → 확정)
- **2차 목표**: 논문용 프로토타입 (AI 후보 vs 교사 확정 비교 등 유효성 지표 산출)

### 절대 원칙 (설계 전반에 강제)
- AI 분석의 **중심 데이터는 영상**(교사 시점). 오디오는 **보조 증거**일 뿐이다.
- AI는 관찰기록을 **확정하지 않는다.** 후보만 제시하고, 교사가 검토·수정·확정한다.
- AI는 유아를 자동 확정 식별하지 않는다. `child_A`, `child_B` 임시 ID만 부여하고, **교사가 실제 가명 ID와 매칭**한다.
- 1차 분류 기준 = **누리과정 5개 영역**. **KICCE 유아관찰척도 60문항 매핑은 핵심 기능**(연구로 1차 검증된 관찰 지표). 단, AI는 **문항 후보를 제시할 뿐 확정하지 않으며**, 교사의 관찰기록 판단을 지원한다. 향후 친사회성·놀이몰입·자기조절 등 심화 척도로 매핑을 확장한다.
- **관찰수준 점수는 산출하지 않는다.**
- 원본 영상은 **제한 접근 · 접근 로그 · 삭제 정책**을 가진다.
- 영상 전체를 무조건 외부 API에 보내지 않는다. **장면 분할 후 주요 프레임/짧은 클립 단위**로만 전송한다.
- Neo4j 미사용. 1차는 SQLite + 로컬 JSON/CSV. 모듈을 분리해 향후 PostgreSQL/FastAPI/Next.js 확장이 가능하게 한다.

## 1. 최종 기술 스택

| 영역 | 선택 | 비고 |
|------|------|------|
| 언어 | Python 3.11+ | 단일 언어 코드베이스 |
| UI | **Streamlit** | 교사 검토 화면 + 연구자 리포트 |
| 영상 디코딩/오디오 추출 | ffmpeg, OpenCV | 프레임 디코딩, 오디오 분리 |
| 장면 분할 | **PySceneDetect** (content-aware) | 컷/장면 경계 검출 |
| 프레임 품질 필터 | OpenCV (Laplacian 분산) | 흐림/저품질 프레임 제거 |
| 비전 분석 | 클라우드 멀티모달 LLM API (Gemini / GPT-4o / Claude 중 1개) | **이미지(프레임/그리드) 입력**. 어댑터로 교체 가능 |
| 오디오 전사(보조) | faster-whisper (로컬 우선) | 타임스탬프 포함 STT |
| 저장소 | **SQLite** (1차) + JSON/CSV export | repository 패턴으로 추상화 |
| 설정 | pydantic-settings + `.env` | API 키, 경로, 비용 상한 |
| 로깅/감사 | Python logging + `audit_log` 테이블 | 영상 접근/삭제 기록 |

**배포 형태**: 로컬 앱(온프레미스) + 비전/STT 분석 시에만 클라우드 AI API 호출.
원본 영상은 로컬 제한 접근 디렉토리에 보관, 외부로는 선별된 프레임/클립만 전송.

### 모듈 구조 (확장 대비 분리)
```
smartglass-child-observation/
├─ app/                      # Streamlit 진입점 (UI 전용, 도메인 로직 없음)
│  ├─ Home.py
│  └─ pages/
│     ├─ 1_업로드_분석.py
│     ├─ 2_교사_검토.py
│     └─ 3_연구자_리포트.py
├─ core/                     # 도메인 모델·스키마 (UI/저장소 독립)
│  ├─ schemas.py             # Pydantic: 관찰후보, 프레임메타, 매핑 등
│  └─ constants.py           # 누리 5영역 등 상수
├─ services/                 # 분석 파이프라인 (재사용 가능, UI 비의존)
│  ├─ video/                 # 장면분할·프레임추출·품질필터
│  ├─ vision/                # 비전 LLM 어댑터(인터페이스 + 구현)
│  ├─ audio/                 # 오디오 추출 + STT(보조)
│  ├─ mapping/               # 누리/KICCE 매핑
│  └─ pipeline.py            # 단계 오케스트레이션
├─ storage/                  # repository 패턴 (SQLite 구현, 추후 PG 교체)
│  ├─ repository.py          # 추상 인터페이스
│  └─ sqlite_repo.py
├─ resources/                # 누리과정/KICCE 기준 데이터(JSON/CSV)
│  ├─ nuri_areas.json
│  └─ kicce_items.json
├─ data/                     # (gitignore) 영상·프레임·DB — 제한 접근
│  ├─ videos/                # 원본 영상 (접근 제한)
│  ├─ frames/                # 추출 프레임
│  └─ app.db
├─ security/                 # 접근 제어·감사 로그·삭제 정책
├─ config.py                 # pydantic-settings
└─ docs/                     # 프로젝트 문서
```

## 2. 영상 중심 AI 분석 파이프라인

```
[1] 업로드/검증     영상 파일 업로드, 메타(길이·해상도·fps) 추출, 제한 디렉토리 저장 + 접근 로그
        ↓
[2] 장면 분할       PySceneDetect로 콘텐츠 기반 장면 경계 검출 → 시간 구간 목록(segments)
        ↓
[3] 프레임 추출     장면별 대표 프레임 + 품질 필터(흐림 제거) + 프레임 수 상한(비용 통제)
        ↓
[4] (보조) 오디오   ffmpeg로 오디오 분리 → faster-whisper STT(타임스탬프) → 구간에 시간 정렬
        ↓
[5] 비전 분석       구간 단위로 프레임(+있으면 STT 텍스트)을 비전 LLM에 전송 → 관찰 후보 JSON
        ↓
[6] 후보 통합       구간별 후보 병합, temp_child_id(child_A/B) 정규화, 중복 정리
        ↓
[7] 누리/KICCE 매핑 누리 5영역 1차 분류 → KICCE 문항 후보 부착, 근거 포함
        ↓
[8] 교사 검토       child 매칭, 후보 채택/수정/기각, 자유 편집 → 확정
        ↓
[9] 리포트          유아별 관찰기록 + AI후보 대비 교사확정 비교 지표
```
- 각 단계 산출물은 SQLite + JSON으로 저장 → 재현 가능, 단계 재실행 가능.
- 외부 전송은 [5]에서만 발생하며, **선별된 프레임/클립 + 해당 구간 텍스트**로 한정.

> 파이프라인 상세는 [05_AI_PIPELINE.md](05_AI_PIPELINE.md) 참조.

## 3. 1차 개발 단계 (시연 우선)

| 단계 | 내용 | 산출물 |
|------|------|--------|
| **P0 셋업** | 모듈 구조 생성, config, resources(누리/KICCE 데이터), `.gitignore`(data/) | 빈 골격 + 실행되는 Streamlit Home |
| **P1 영상 파이프라인** | 업로드 → 장면 분할 → 프레임 추출 → 품질 필터 | 프레임/메타 DB 저장 |
| **P2 비전 분석** | 비전 LLM 어댑터, 입력 구성, 출력 JSON 스키마 검증, 후보 생성 | 구간별 관찰 후보 |
| **P4 KICCE 매핑 (핵심)** | 누리 영역 후보 → KICCE 문항 후보 매칭(키워드/규칙 + 임베딩 유사도), 근거·신뢰도, 척도 플러그 인터페이스 | 문항 후보가 붙은 관찰기록 |
| **P5 교사 검토 UI** | 플레이어, child 매칭, 후보 채택/수정/기각, 확정 | 확정 관찰기록 |
| **P3 오디오 보조** | 오디오 분리 + STT 정렬, `audio_support` 주입 | 보조 텍스트 부착 |
| **P6 연구자 리포트** | 분포·커버리지·후보 대비 확정 비교·export | 리포트 화면 |
| **P7 보안/정책** | 제한 접근 디렉토리, 접근/삭제 감사 로그, 삭제 정책 | security 모듈 |
| **P8 시연 리허설** | 샘플 영상 1~2개로 전 파이프라인 리허설, 비용·시간 측정 | 발표 시나리오 |

> 권장 시연 경로: **P0 → P1 → P2 → P4 → P5**(핵심 데모) 우선 완성.
> **P4(KICCE 매핑)는 시스템의 핵심 가치이므로 최소 데모에 포함**한다.
> P3(오디오 보조)는 보강 기능으로 일정에 따라 후순위 조정 가능.
> 척도 확장(친사회성·놀이몰입·자기조절)은 P4의 플러그 인터페이스 위에서 2차 진행.
