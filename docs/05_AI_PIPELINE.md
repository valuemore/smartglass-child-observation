# 05. AI 분석 파이프라인 (상세)

> **분석 방식: 프레임 추출 + 비전 모델.** 중심은 영상이며 오디오는 보조 증거다.
> AI는 후보만 제시하고 확정하지 않는다. 점수는 산출하지 않는다.

## 1. 전체 흐름

```
[A. 매일 자동 누적 — 업로드 즉시 동기 실행]
업로드/검증 → 장면 분할 → 프레임 추출(+품질 필터) → 근거 클립 추출 → (보조)오디오 STT
→ 비전 분석(구간/클립 단위) → (동의 ON 시) 얼굴 매칭 후보 → 후보 통합 → 누리/KICCE 매핑 → 후보 누적

[B. 수시] 수집 현황 집계(유아×누리영역)

[C. 1~2주 주기, 교사 트리거] 주간 초안 생성(대표 근거 클립) → (교사 검토·확정) → (리포트)
```
- 각 단계 산출물은 SQLite + JSON으로 저장(재현·재실행 가능).
- **A는 업로드 즉시 자동 실행**되며 교사 후보 검토 게이트가 없다(별도 스케줄러 미도입, 동기 처리).
- 외부 API 전송은 **비전 분석 단계에서만**, **선별 프레임/클립 + 해당 구간 텍스트**로 한정.
  **얼굴 참조사진·얼굴 임베딩·원본 영상은 전송하지 않는다.**

## 2. 프레임 추출 전략

1. **장면 경계 검출**: PySceneDetect `ContentDetector` → `segments[{start, end}]`.
2. **장면별 대표 프레임**: 각 장면에서 시작·중간·끝 또는 키프레임 1~3장.
3. **긴 장면 보강 샘플링**: 장면이 길면(> N초) 균등 간격(예: 2~3초)으로 추가 프레임.
4. **품질 필터**: Laplacian 분산 기반 흐림 탐지로 저품질 프레임 제거(임계값 설정).
5. **비용 상한**: 영상당/구간당 최대 프레임 수 상한으로 API 토큰·비용 통제.
6. **동작 맥락 옵션**: 행동이 모호한 구간은 **연속 프레임 그리드(2×2 등)** 또는 짧은 클립으로 묶어
   1회 입력 → "행동의 흐름"을 비전 모델이 읽도록.
7. 추출 프레임은 `data/frames/{video_id}/{segment_id}/`에 저장, 메타를 DB에 기록.

## 3. 오디오의 보조 활용

- ffmpeg로 오디오 분리 → faster-whisper STT(타임스탬프 포함).
- **발화가 명확한 구간만** 사용. 잡음·불명확 발화는 버림.
- 화자 구분은 휴리스틱/표기 수준(`teacher`/`child`/`unknown`), 확정하지 않음.
- 비전 분석 구간에 **시간 정렬**해 보조 텍스트로 동봉.
- STT 단독으로 관찰기록을 생성하지 않는다. 영상 기반 관찰의 **근거 보강** 전용.

## 4. 비전 모델 입력 데이터 구조

```json
{
  "video_id": "vid_001",
  "segment_id": "seg_007",
  "time_start": 132.4,
  "time_end": 138.9,
  "frames": [
    {"frame_id": "f_021", "t": 132.5, "image_ref": "data/frames/.../f_021.jpg"},
    {"frame_id": "f_022", "t": 135.0, "image_ref": "..."}
  ],
  "frame_layout": "sequence|grid_2x2",
  "audio_support": {
    "available": true,
    "transcript": "(교사) 블록 더 높이 쌓아볼까? (유아) 무너졌어!",
    "speaker_hint": "teacher|child|unknown"
  },
  "instruction_context": {
    "nuri_areas": ["신체운동·건강", "의사소통", "사회관계", "예술경험", "자연탐구"],
    "rules": [
      "유아를 확정 식별하지 말 것. child_A, child_B 임시 ID만 부여.",
      "각 관찰에 반드시 시각적 근거(어떤 프레임/무엇이 보였는지) 포함.",
      "신뢰도(0~1)와 교사 확인 필요 여부 표기.",
      "관찰수준 점수는 산출하지 말 것.",
      "오디오는 보조 증거로만 활용."

  }

```
- 이미지는 API 규격에 맞게 base64/파일 첨부. 텍스트(STT)는 보조로 동봉.

## 5. 비전 모델 출력 JSON 구조

```json
{
  "segment_id": "seg_007",
  "time_start": 132.4,
  "time_end": 138.9,
  "observations": [
    {
      "temp_child_id": "child_A",
      "observed_behavior": "블록을 수직으로 쌓아 올리다가 무너지자 다시 시도함",
      "interaction": {
        "with_peers": "child_B와 번갈아 블록을 올림",
        "with_teacher": "교사의 '더 높이 쌓아볼까' 제안에 반응",
        "with_materials": "원목 블록 다수 사용"
      },
      "activity_context": "자유놀이 시간 쌓기놀이 영역",
      "peer_relation": "또래와 협력적 차례 주고받기",
      "visual_evidence": "f_021에서 두 손으로 블록을 정렬, f_022에서 무너진 블록을 응시",
      "audio_support": "(유아) '무너졌어!' 발화 — 보조 근거",
      "nuri_area_candidates": [
        {"area": "자연탐구", "rationale": "구조물 균형·인과 탐색", "confidence": 0.72},
        {"area": "사회관계", "rationale": "또래와 협력", "confidence": 0.6}
      ],
      "kicce_item_candidates": [
        {"item_id": 34, "item_text": "...", "rationale": "...", "confidence": 0.55}
      ],
      "confidence": 0.68,
      "needs_teacher_review": true
    }
  ]
}
```
**필수 필드**: `time_start/end`, `observed_behavior`, `visual_evidence`, `confidence`, `needs_teacher_review`.
점수 필드 없음. `temp_child_id`는 교사 매칭 전 임시값. `core/schemas.py`로 검증.

## 6. 누리과정 · KICCE 매핑 (핵심 기능)

KICCE 매핑은 보조가 아니라 **이 시스템의 핵심 가치**다. 영상에서 산출된 관찰 사례를
**연구로 1차 검증된 KICCE 유아관찰척도의 누리 영역·문항 후보와 매칭**해 교사의 판단을 지원한다.

- **누리과정 5영역**(1차 분류): 신체운동·건강 / 의사소통 / 사회관계 / 예술경험 / 자연탐구.
  - `resources/nuri_areas.json`에 영역·내용범주 정의.
- **KICCE 59문항**(핵심 매핑 대상): `resources/kicce_items.json`에
  문항ID·문항텍스트·소속 누리 영역·**관찰사례 예시**·키워드를 구조화 보관.
- **매핑 흐름**:
  1. 비전 모델이 관찰 후보별 **누리 영역 후보**를 근거와 함께 제시(1차 분류).
  2. 매핑 서비스가 관찰 행동 서술 ↔ KICCE 문항을 매칭해 **문항 후보 + 근거 + 신뢰도** 산출.
     - 1차: 누리 영역 필터 + 키워드/규칙 기반 인덱싱.
     - 강화(권장): 관찰 서술과 문항·관찰사례 텍스트의 **임베딩 유사도 검색** → 상위 후보 → LLM 근거 보강.
  3. 결과는 **문항 후보 목록**으로 노출. 확정·점수화하지 않음.
  4. 교사가 검토 화면에서 문항 후보를 채택/수정/기각해 관찰기록에 반영.
- **척도 플러그 구조**: `services/mapping/`의 `ScaleMapper` 인터페이스.
  - 1차 = **KICCE 59문항** 중심.
  - 확장(2차+): **친사회성·놀이몰입·자기조절** 등 심화 척도를 동일 인터페이스로 추가.
  - 각 척도는 `resources/`에 데이터 파일로 분리해 코드 변경 최소화.

## 6-1. 얼굴 참조 매칭 후보 (동의 기반, 로컬 전용)

- 클래스/유아 **동의가 ON일 때만** 수행. OFF면 매칭 미실행(`temp_child_id`만 유지).
- 검출 얼굴의 임베딩 ↔ 등록 `child.face_embedding` **유사도를 로컬에서 비교** → `temp_child_id`별 **가명 매칭 후보 + 신뢰도** 산출.
- 산출물은 `face_match_candidate(status=proposed)`. **확정은 교사**(자동 확정 금지).
- 얼굴 참조사진·임베딩은 **외부 비전 API로 전송하지 않는다**. 매칭 후보는 관찰 출력 스키마와 **별도 산출물**로 분리(기존 관찰 JSON 구조 불변).
- 매칭 수행·참조사진 접근은 `audit_log(face_match / reference_photo_access)`로 기록.

## 6-2. 주간/격주 관찰기록 초안 생성 (교사 트리거)

- 입력: 기간(1주/2주)·대상(유아/영역). 누적 `observation_candidate` + `scale_mapping`을 **유아·영역별로 집계**.
- 구성: 행동 요약·근거·누리/KICCE 후보·**대표 근거 클립 1~3개**(신뢰도·시각 근거 기준)를 텍스트 번들로 구성.
- 생성: LLM이 영역별 **관찰기록 초안(후보)** 텍스트 생성. 근거는 clip id로 인용. **점수·진단·평정 없음.**
- 초안은 후보 → 교사가 검토·수정·확정 → `final_record`(주차 메타).
- (선택) 집계·연결 분석은 SQLite 파생 **인메모리 그래프 투영(NetworkX)** 으로 보조 가능(Neo4j 미사용, [03_DATA_MODEL.md](03_DATA_MODEL.md) §5).

## 7. 비용·안정성 통제

- 프레임 수 상한(영상당/구간당)으로 토큰·비용 제어.
- 비전 호출 실패 시 재시도·백오프, 부분 실패 허용(구간/클립 단위 재실행).
- 업로드 즉시 자동 분석은 **상태머신**(queued/running/done/failed)·진행률·재시도로 안정성 확보.
- 모든 외부 전송 페이로드에 **원본 영상·얼굴 참조사진·얼굴 임베딩이 포함되지 않음**을 보장.

## 8. 원칙 점검 (이 단계에서 반드시 보장)

- [ ] 영상 중심, 오디오는 보조에만 사용.
- [ ] AI는 후보만 제시(자동 확정 없음).
- [ ] 유아는 임시 ID + **얼굴 매칭 후보**까지만, **자동 신원 확정 없음**(교사 확정). 얼굴 매칭은 동의 기반.
- [ ] 누리 1차 분류 + KICCE 문항 후보(핵심) 제시.
- [ ] 관찰수준 점수·**발달 점수·평정 점수** 미산출.
- [ ] 외부 전송은 선별 프레임/클립 + 텍스트로 한정. **얼굴 참조사진·임베딩·원본 영상 미전송.**
- [ ] 주간 초안은 후보이며 교사 확정 전까지 기록이 아님.
