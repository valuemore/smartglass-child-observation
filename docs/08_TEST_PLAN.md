# 08. 테스트 · 검증 계획

> 1차는 시연 안정성 검증이 목적. 단계별 수용 기준과 원칙 준수 체크리스트를 둔다.

## 1. 단계별 수용 기준

| 단계 | 검증 항목 | 통과 기준 |
|------|-----------|-----------|
| P0 셋업 | `streamlit run app/Home.py` | 빈 앱이 오류 없이 실행됨 |
| P1 영상 | 샘플 영상 업로드→분할→추출 | 장면 수·추출/유지 프레임 수가 UI/DB에 표시, 흐림 프레임 제거 확인 |
| P2 비전 | 구간 비전 출력 JSON | `core/schemas.py` 검증 통과, 필수 필드 포함 |
| P4 매핑(핵심) | KICCE 문항 후보 매핑 | 후보가 **근거·신뢰도와 함께** 부착, 누리 영역 필터 정확 |
| P5 검토 UI | child 매칭·채택/수정/기각·확정 | 확정 기록이 `final_record`에 저장 |
| P3 오디오 | STT 보조 정렬 | 명확 발화 구간만 `audio_support`로 주입 |
| P6 리포트 | 분포·커버리지·비교 지표 | 누리 분포·KICCE 커버리지·AI vs 교사 지표 산출 |
| P7 보안 | 접근/삭제 로그·전송 가드 | `audit_log` 기록, 전송 페이로드에 원본 영상 없음 |
| P8 리허설 | 전 파이프라인 시연 | 샘플 영상으로 끊김 없이 완주, 비용·시간 측정 |

## 2. 검증 절차 (end-to-end)

1. `streamlit run app/Home.py` 실행 확인.
2. 샘플 영상 업로드 → 장면/프레임 결과 확인.
3. 배치 분석 → 관찰 후보 JSON 스키마 검증.
4. KICCE 문항 후보가 근거·신뢰도와 함께 매핑되는지 확인.
5. child_A→가명 ID 매칭, 후보 채택/수정/기각 → 확정 저장 확인.
6. 리포트에서 분포·커버리지·AI vs 교사 비교 확인.
7. 영상 접근/삭제가 `audit_log`에 남고, 외부 전송 페이로드에 원본 영상이 없음을 확인.

## 3. 원칙 준수 체크리스트 (릴리스 전 필수)

- [ ] 영상 중심 분석, 오디오는 보조에만 사용.
- [ ] AI는 후보만 제시(자동 확정 없음), 교사 확정 단계 존재.
- [ ] 유아는 임시 ID만, 가명 매칭은 교사가 수행(자동 신원 확정 없음).
- [ ] 누리 5영역 1차 분류 + KICCE 문항 후보(핵심) 제시.
- [ ] **관찰수준 점수 미산출.**
- [ ] 외부 전송은 선별 프레임/클립 + 텍스트로 한정, 원본 영상 미전송.
- [ ] 영상 접근/삭제 감사 로그 동작, 비밀값은 `.env`(git 제외).

## 4. 테스트 데이터

- 실제 스마트안경 또는 **유사 시점으로 촬영한 샘플 영상 1~2개**(IRB·동의 범위 내).
- 민감 데이터는 저장소에 커밋하지 않는다(`data/`는 git 제외).

## 5. 테스트 종류 (구현 단계에서 추가)

- 단위: 프레임 추출·품질 필터·매핑 규칙·스키마 검증.
- 통합: 파이프라인 단계 연결(모의 비전 어댑터로 외부 호출 대체).
- 시연 리허설: P8에서 전체 흐름·소요 시간·비용 측정.

> 본 문서는 문서화 단계의 계획이며, 실제 테스트 코드는 이후 개발 단계에서 작성한다.
