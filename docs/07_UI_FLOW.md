# 07. UI 흐름 (Streamlit)

> 1차 UI는 Streamlit. `app/`은 화면·입력·표시만 담당하고 도메인 로직은 `services/`에 둔다.
> 화면 텍스트는 한국어.

## 1. 화면 구성

```
Home (개요·영상 목록)
├─ 1_업로드_분석     영상 업로드 → 배치 분석 실행 → 진행 상태
├─ 2_교사_검토       플레이어 + child 매칭 + 관찰 후보 검토·확정
└─ 3_연구자_리포트   영역 분포·문항 커버리지·AI vs 교사 비교·export
```

## 2. 전체 사용자 흐름

```
[교사] 영상 업로드 ─▶ 배치 분석 ─▶ 후보 생성 완료
          │
          ▼
[교사] 교사 검토 화면
   1) child_A/B ↔ 가명 ID 매칭
   2) 구간별 관찰 후보 카드 확인 (시각 근거·누리·KICCE 후보·신뢰도)
   3) 채택 / 수정 / 기각
   4) 확정 → final_record 저장
          │
          ▼
[연구자] 리포트 열람 / export
```

## 3. 화면별 상세

### Home
- 업로드된 영상 목록(상태: uploaded/analyzing/analyzed/reviewed).
- 영상 열람 시 "접근이 감사 로그에 기록됨" 안내.
- 영상별 삭제 요청 버튼.

### 1_업로드_분석
- 영상 파일 업로드(제한 디렉토리 저장, 메타 추출).
- "배치 분석 실행" 버튼 → 파이프라인(장면 분할→프레임→(보조)STT→비전→매핑) 진행 표시.
- 결과 요약: 장면 수, 추출/유지 프레임 수, 생성된 관찰 후보 수.

### 2_교사_검토 (핵심 화면)
- **영상 플레이어 + 타임라인**: 장면/구간 마커, 후보가 있는 구간 강조.
- **child 매칭 패널**: `child_A`, `child_B` → 가명 ID 드롭다운. 매칭 시 전체 후보에 일괄 반영.
- **구간별 관찰 후보 카드**:
  - 시각적 근거 프레임 썸네일
  - 관찰 행동 텍스트 / 상호작용(또래·교사·자료) / 활동 맥락
  - 누리 영역 후보(칩) / KICCE 문항 후보(접이식) / 신뢰도 게이지 / `교사 확인 필요` 배지
  - 액션: **채택 / 수정(자유 편집) / 기각**
- **확정 버튼**: 채택·수정 항목을 `final_record`로 저장(작성자·시각 기록).

```
┌──────────────── 2_교사_검토 ────────────────┐
│ [▶ 영상 플레이어]      타임라인 ▣─▣─▣─▣      │
│                                              │
│ child 매칭:  child_A → [가명ID ▼]            │
│             child_B → [가명ID ▼]            │
│ ─────────────────────────────────────────── │
│ ┌ 후보 카드 (seg_007, 132.4~138.9s) ───────┐ │
│ │ [썸네일][썸네일]   신뢰도 ▰▰▰▰▱  ⚠확인필요 │ │
│ │ 행동: 블록을 쌓다가 무너지자 다시 시도…     │ │
│ │ 누리: [자연탐구][사회관계]                 │ │
│ │ KICCE 후보 ▸ 34번 …                        │ │
│ │ [채택] [수정] [기각]                       │ │
│ └────────────────────────────────────────── ┘ │
│           ... 다음 후보 ...      [확정 저장]   │
└──────────────────────────────────────────────┘
```

### 3_연구자_리포트
- 유아별(가명 ID) 확정 관찰기록 모음(시간순).
- 누리 5영역 분포 차트.
- KICCE 문항 커버리지(후보 기준).
- **AI 후보 vs 교사 확정 비교**: 채택률·수정률·기각률, 신뢰도 구간별 채택률.
- 활동 맥락 타임라인.
- Export: JSON/CSV + 발표용 요약. **관찰수준 점수 미산출** 명시.

## 4. UI 원칙

- AI 결과는 항상 **"후보"** 로 표기. 확정은 교사 액션으로만 발생.
- 모든 후보에 시각적 근거와 신뢰도를 함께 노출.
- child 매칭 전에는 임시 ID(`child_A/B`)로만 표시.
- 점수 표기 없음.
