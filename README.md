# 스마트안경 유아 행동 관찰기록 보조 시스템

어린이집 교사가 착용한 **스마트안경(교사 1인칭 시점)** 영상을 **매일 업로드·자동 분석**해
유아의 행동·상호작용·활동 맥락 관찰기록 **초안(후보)** 을 **누적**하는 **상시 현장 검증형** 연구용 웹 시스템입니다.
교사는 **수집 현황을 수시 확인**하고 **1~2주 주기로 초안을 검토·수정·확정**합니다.
AI는 기록을 확정하지 않으며, **교사가 최종 확정**합니다.

## 운영 모델 (V2)

1. 교사가 **매일** 스마트안경 영상을 업로드 → 시스템이 **업로드 즉시** 전처리·클립 추출·AI 분석·유아 매칭 후보·누리/KICCE 후보를 **자동 누적**.
2. 교사는 **매일 개별 후보를 검토하지 않고**, 유아별·누리영역별 **수집 현황만 확인**해 부족한 부분을 다음 촬영에서 보완.
3. 교사가 **1~2주 주기**로 누적 후보 기반 **관찰기록 초안을 검토·수정·확정**.
4. 연구자는 AI가 교사의 관찰기록 작성을 **얼마나 지원했는지** 검증.

## 목적

- **1차 목표**: 학회 발표용 시연 시스템 (1~2주 누적 → 주간 초안 확정 → 지원도 지표)
- **2차 목표**: 논문용 프로토타입 (AI 후보 vs 교사 확정 비교 등 유효성 지표 산출)

## 핵심 원칙

- AI 분석의 중심 데이터는 **영상**이며, 오디오는 **보조 증거**다.
- AI 분석 방식은 **프레임 추출 + 비전 모델**이다.
- AI는 관찰기록을 **확정하지 않고 후보만 제시**한다.
- AI는 유아를 자동 식별·확정하지 않는다. `child_A`, `child_B` 임시 ID를 부여하고 등록된 **얼굴 참조사진 대비 가명 매칭 후보**까지 제시하며, **확정은 교사**가 한다. 얼굴 매칭은 **기본 OFF·연구 동의 시 ON**.
- 1차 분류 기준은 **누리과정 5개 영역**, **KICCE 유아관찰척도 59문항 매핑은 핵심 기능**이다(후보 제시).
- **관찰수준 점수·발달 점수·평정 점수는 산출하지 않는다.**
- 원본 영상·**얼굴 참조사진·얼굴 임베딩**은 **제한 접근 · 접근 로그 · 삭제 정책**을 따르며 외부로 전송하지 않는다.
- 교사는 **매일 검토하지 않고** 수집 현황만 확인하며, **주기적(1~2주)으로 확정**한다.

## 기술 스택

Python 3.11+ · Streamlit · OpenCV/ffmpeg · PySceneDetect · 클라우드 멀티모달 비전 LLM API ·
faster-whisper(보조 STT) · 로컬 얼굴 검출·임베딩(동의 기반) · SQLite.
**배포는 로컬 앱 + 클라우드 AI API**, **입력은 매일 영상 업로드 + 업로드 즉시 자동 분석·누적**.
Neo4j는 사용하지 않습니다(그래프 분석은 SQLite 파생 인메모리 투영으로 한정).
향후 PostgreSQL/FastAPI/Next.js로 확장 가능하도록 모듈을 분리합니다.

## 현재 상태

V1(업로드→배치 분석→교사 검토→확정) 구현 완료. **V2 상시 현장 검증형 전환 진행 중**입니다
(문서 기준 갱신 → 데이터 모델 확장 → 자동 분석·대시보드·주간 초안·얼굴 매칭 단계).

## 디렉토리 개요

```
app/         Streamlit UI (진입점, 도메인 로직 없음)
core/        도메인 모델·스키마·상수
services/    분석 파이프라인 (video / vision / audio / mapping / face / dashboard / draft)
storage/     저장소 추상화 (SQLite 구현)
resources/   누리과정·KICCE 기준 데이터
data/        영상·프레임·클립·얼굴 참조사진·DB (git 제외, 제한 접근)
security/    접근 제어·감사 로그·삭제 정책
docs/        프로젝트 문서
```
